# 05 · מנוע ה-AI לגבייה (AI Dunning Engine)

זהו לב-המוצר והבידול מול כל מתחרה: לא טמפלייט קבוע, אלא AI שמחליט **מה לכתוב,
מתי, באיזה ערוץ, ובאיזה טון** — פר-לקוח, פר-הקשר — ולומד מה גובה כסף.

## 5.1 ארבע ההחלטות של המנוע

לכל חשבונית-פתוחה המנוע מחליט בכל נקודת-זמן:

1. **מה לכתוב (Content):** ניסוח הודעה מותאם — מתחשב בשם-הלקוח, סכום, כמה ימים
   באיחור, היסטוריית-תשלומים, וטון-המותג. אדיב בהתחלה, נחרץ בהדרגה.
2. **מתי לשלוח (Timing):** היום והשעה בעלי-הסיכוי-הגבוה-ביותר לתגובה (לפי דפוסי-
   עבר של הלקוח/הסגמנט).
3. **באיזה ערוץ (Channel):** אימייל [MVP] → ובהמשך SMS/WhatsApp לפי מה שעובד.
4. **האם להסלים (Escalation):** להמשיך עדין, להעלות-מדרגה, או לסמן להתערבות-אדם.

## 5.2 איך נבנית הודעה (Generation)

- **קלט (context):** נתוני-חשבונית + פרופיל-לקוח + היסטוריה + טון-מותג + שלב-ברצף.
- **תבנית-מובנית + AI:** prompt-template עם משתנים, וה-LLM מנסח גרסה טבעית
  ומותאמת (לא "מילוי-חוסר" מכני). פלט כולל: נושא, גוף, ורמת-נחרצות.
- **רב-לשוני:** עברית/אנגלית לפי הלקוח.
- **תמיד כולל:** הקשר-ברור (איזו חשבונית, סכום, תאריך), לינק-תשלום, ופרטי-קשר.

### דוגמת-הסלמה (סכמטי)
```
+0 (יום היעד):    "רק תזכורת ידידותית — חשבונית #123 על ₪18,000 מגיעה היום 🙂 [לתשלום]"
+7:               "היי, נראה שחשבונית #123 עוד פתוחה — אשמח לעזור אם יש משהו שתקוע. [לתשלום]"
+14:              "תזכורת שנייה: חשבונית #123 באיחור של שבועיים. אפשר להסדיר כאן: [לתשלום]"
+30:              "חשבונית #123 באיחור של 30 יום. נשמח להסדרה עד [תאריך] כדי להימנע מהסלמה."
                  → במקביל: התראה לבעל-העסק לאישור/התערבות.
```

## 5.3 לולאת-הלמידה (Learning Loop)

- כל הודעה נרשמת עם **תוצאה**: נפתחה? נלחץ הלינק? שולם? תוך כמה זמן?
- המנוע מזהה **מה עובד** (איזה נוסח/תזמון/ערוץ מביא לתשלום) פר-סגמנט וורטיקל,
  ומכוון את ההחלטות הבאות.
- זהו ה**חפיר**: ככל שעוברות יותר חשבוניות, ההחלטות מדויקות יותר — יתרון מצטבר.

> ב-MVP: היוריסטיקות + A/B פשוט. בהמשך: מודל-אופטימיזציה על נתוני-התוצאה.

## 5.4 Guardrails ובטיחות-טון (קריטי)

המוצר שולח בשם-העסק → הודעה גרועה אחת פוגעת ביחסי-הלקוח שלו. לכן:

- **גבולות-טון קשיחים:** אף פעם לא מאיים, מעליב, או "חברת-גבייה". סף-נחרצות
  מקסימלי מוגדר.
- **Human-in-the-loop:** אישור-אדם לפני הסלמות "חזקות"; **Approval mode** מלא
  בתחילת-הדרך (המשתמש מאשר כל הודעה עד שנבנה אמון).
- **עצירה אוטומטית:** חשבונית "במחלוקת" / תגובת-לקוח → המנוע עוצר ומתריע (לא רודף
  אחרי כסף שנוי-במחלוקת).
- **Brand-safety filter:** סינון פלט-AI לפני שליחה (איסור-תוכן, עובדות-שגויות
  כמו סכום/תאריך לא-תואמים, שפה לא-הולמת).
- **תאימות-רגולציה:** שמירה על כללי-תקשורת (CAN-SPAM/TCPA/הסכמות) — ראו
  [פרק 10](10-roadmap-risks-compliance.md).

## 5.5 טיפול בקלט לא-אמין / Edge cases
- נתוני-חשבונית חסרים/שגויים → בקשת-השלמה מהמשתמש לפני שליחה.
- לקוח עונה "כבר שילמתי" → עצירה + התראה + בקשת-אימות מול הסטטוס.
- כתובת-מייל לא-תקינה / bounce → דגל + הצעת-ערוץ-חלופי.
- מניעת spam/over-sending → תקרת-תדירות פר-לקוח.

## 5.6 ממשק-AI (ל-handoff לפיתוח)
- שכבת-AI מאחורי ממשק אחיד: `generateReminder(context) → {subject, body, urgency}`
  ו-`decideNextAction(invoiceState) → {action, channel, sendAt}`.
- ניתנת-להחלפה (ספק-LLM), עם logging מלא של prompt/פלט/תוצאה לצורך למידה ואודיט.
- ברירת-מחדל: ספק-LLM מוביל (למשל Claude) + embeddings לסגמנטציה.
