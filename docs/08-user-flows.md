# 08 · זרימות משתמש (User Flows)

פירוט מסך-אחר-מסך לתרחישים המרכזיים, כולל מצבים (states) ו-edge cases. הזרימות
מתוארות למסלול ה-Gig (הליבה ל-MVP); וריאציות-מסלול מצוינות במקום הרלוונטי.

## 8.1 Onboarding (קליטה)

```
[Landing] → [הרשמה: אימייל/SSO] → [בחירת תפקיד: Talent / Client / Both]
   → [AI Gatekeeper: אימות זהות KYC] → [AI Onboarding Audit:
       חיבור GitHub/Figma/LinkedIn + ראיון-AI קצר]
   → [פרופיל מובנה + seed Trust Index] → [Dashboard]
```
- **States:** ממתין-אימות · אומת · נדחה · נדרש-מידע-נוסף.
- **Edge cases:** ללא נוכחות-דיגיטלית → אימות-וידאו; כשל-KYC → מסלול ידני;
  משתמש כפול → חסימה.

## 8.2 פרסום צורך / חיפוש התאמה (Client)

```
[Dashboard] → ["פרסם פרויקט" או "מצא טאלנט"] → [AI Scope Assistant:
   ניסוח scope, אבני-דרך, תקציב] → [Semantic Matching: רשימת התאמות מדורגת
   + "ציון התאמה" + הסבר] → [שליחת התעניינות]
```
- **Edge cases:** אין היצע תואם → התראה + גיוס-יזום/רשימת-המתנה; תקציב לא-ריאלי →
  המלצת-תיקון.

## 8.3 Progressive Disclosure → הסכמה

```
[התעניינות הדדית] → [שלב 1: פרופיל מצומצם] → [שלב 2: זהות + פרטים]
   → [צ'אט ב-Workspace] → [סיכום scope] → [AI Contract Drafting:
       חוזה + אבני-דרך לחתימה] → [חתימה דיגיטלית הדדית]
```
- **Edge cases:** אי-הסכמה על scope → סבב-תיקון; ניסיון החלפת פרטי-קשר מוקדם →
  התראת-disintermediation.

## 8.4 נעילת Escrow ותחילת עבודה

```
[חוזה חתום] → [Client טוען אבן-דרך 1 ל-Escrow] → [אישור נעילה לשני הצדדים]
   → [Talent מתחיל; Kickoff Check-in] → [Workspace פעיל: צ'אט, קבצים, סטטוס]
```
- **States:** ממתין-טעינה · Escrow-נעול · בעבודה.
- **Edge cases:** Client לא טוען Escrow → לא ניתן להתחיל (הגנת ספק); No-Show
  ל-kickoff → קנס.

## 8.5 מסירה, אימות ושחרור

```
[Talent מגיש אבן-דרך] → [AI Work Verification: בדיקה מול scope + אינטגרציות]
   → [ציון-מסירה] →
       ├─ תקין + אישור-לקוח → [שחרור Escrow לספק] → [אבן-דרך הבאה]
       ├─ לקוח לא-מגיב X ימים → [Auto-Release]
       └─ לקוח מערער → [Dispute Mediation]
```
- **States:** הוגש · מאומת · שוחרר · במחלוקת.
- **Edge cases:** תוצר לא-מדיד → אישור-ידני + חלון-ערעור; מסירה חלקית → שחרור-חלקי.

## 8.6 סכסוך (Dispute)

```
[ערעור] → [שני הצדדים מגישים טענות + ראיות] → [AI Mediation: השוואה ל-scope
   + Activity log] → [הצעת-הכרעה: שחרור מלא/חלקי/החזר] →
       ├─ קבלה → [ביצוע חלוקה] → [עדכון Trust Index]
       └─ ערעור → [בורר אנושי] → [הכרעה סופית]
```
- **Edge cases:** collusion/הונאה-הדדית → חקירה; ערעורים-סדרתיים → חסימת-abuse.

## 8.7 סגירה, דירוג ועבודה חוזרת

```
[עסקה הושלמה] → [דירוג הדדי + משוב מובנה] → [עדכון Trust Index + Trust Badge]
   → [הצעת "עבודה חוזרת" / שמירת-קשר] → [שיתוף Trust Badge חיצוני]
```

## 8.8 וריאציית Equity Track (תמצית)

```
[התאמת co-founders] → [Trial Vesting 30–90 יום] → [אבני-דרך ביצועיות] →
[Dynamic Vesting + עדכון cap-table] → [המשך/פרידה נקייה] → [חתימת Founder Agreement]
```

## 8.9 מצבי-קצה גלובליים (Global Edge States)
- **משתמש נוטש באמצע:** הקפאת-עסקה, חלוקה-הוגנת לפי-ביצוע, פגיעה ב-Trust Index.
- **תקלת-תשלום/freeze:** הודעה שקופה + תוכנית-המשכיות.
- **דיווח-abuse/הטרדה:** השעיה + סקירה.
- **מחיקת-חשבון:** שמירת-מינימום לחובות-Escrow פתוחים + ציות-פרטיות (GDPR).
